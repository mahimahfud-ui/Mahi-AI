# MahiCloud UI Integration Map

## Scope and safety

This change adapts the supplied Claude-generated MahiCloud visual direction to the existing production application. The source UI archives contain a standalone demo: their README explicitly says responses are local samples, and their Settings, Auth, Voice, and Admin panels are mock implementations. Those mock JavaScript files are **not** loaded into the production app. Instead, the existing HTML integration points and live Supabase-backed modules remain the source of truth, with an additive Lagoon presentation layer and a small top-bar theme adapter.

No changes are made to server.js, public/app.js, Supabase Edge Functions, migrations, credentials, provider routing, auth policies, or deployment configuration. No deployment is triggered by this pull request.

## Files changed in this integration

- public/index.html: updated the welcome content to the supplied “Quiet space for clear thinking” design, changed the four prompt cards to match the supplied screenshots, added the visible MahiCloud title and quick theme control, and retained production DOM IDs and script wiring.
- public/mahi.css: existing additive presentation layer refined to match the supplied hero/cards/top bar while retaining dark/light theme tokens, responsive layout, focus indication, and reduced-motion support.
- public/ui-adapter.js: bridges the quick theme button to the original persisted settings control; no duplicate theme state or persistence path.
- tests/redesign-contract.test.cjs: updates the stylesheet cache-version assertion.
- tests/claude-ui-integration.test.cjs: adds regression checks for unique required IDs, retained live scripts, chat/SSE/auth/attachment contracts, and responsive/accessibility CSS.

## Preview and validation

Run Node.js 18 or newer, then execute `npm start` and open http://localhost:3000. The project has no frontend build step. Run targeted checks with `node --test tests/redesign-contract.test.cjs tests/claude-ui-integration.test.cjs`. The repository's complete Node regression suite and the Deno Edge Function suite should also run in CI.

Static checks cannot prove real authentication, provider streaming, Storage uploads, phone SMS, microphone access, or protected admin operations. Those require a valid staging configuration and browser session. Do not deploy Render or Supabase from this pull request.

## Safe rollout / rollback

Review and merge the pull request before deploying. For rollback, revert this pull request; the original public/app.js, voice/admin/code-block modules, server, database migrations and existing Supabase contracts were not changed by this UI integration. A rollback does not require a database migration.
